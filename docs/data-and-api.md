# 数据与接口说明

[← 返回首页](../README.md)

## 本机保存什么

| 内容 | 保存位置与边界 |
| --- | --- |
| API Key 与服务商配置 | 当前 Android 预览版使用设备 Keystore 的 AES-GCM 密钥加密后写入私有目录。升级时读回校验成功，再清理旧的明文配置。 |
| 应用偏好、模板与资料库 | 偏好保存在本机。模板按会话选用，启用记忆的会话会将所列记忆随聊天请求发给选定模型。 |
| 会话和消息树 | IndexedDB；支持消息分支，未提供应用账号或云端同步。 |
| 已保存的附件原件及元数据 | IndexedDB；本机发送的附件原件会保存，聊天 ZIP 仅导出本地可用的图片原件。 |
| 未发送草稿 | IndexedDB 保存文字和附件原件，同步文字日志补足刷新前的写入间隔；恢复的附件需手动重新上传。 |
| 自动备份与恢复点 | 独立 IndexedDB 保存最近生成的 ZIP、保存状态与最近一次替换前快照；属于本机数据，不能替代外部备份。 |
| 头像与昵称 | 本地设置；修改这些信息不会创建服务端账号。 |

清除应用数据或卸载会丢失本机记录。退出登录只清除 API 配置，保留会话；删除全部聊天会清理会话、附件和草稿，保留 API 配置及偏好。

## 哪些内容会发送出去

客户端向当前配置的 API 地址发送模型请求。根据所使用的功能，请求可能包含聊天文本、附件、待转写录音、待朗读正文和压缩摘要所需的历史内容。**手动选择附件后就可能开始上传。** 从 Android 系统分享接收的图片先保存在本地草稿，点发送才会上传。切换会话服务商前，可在会话顶栏核对接收地址以及该会话启用的记忆。

用户手动选择的位置、当前日期、星期与界面语言可随 DeepSeek 请求中的 `latest_reminder` 发送。应用也会向 GitHub 请求更新清单或安装包。导入下载链接、打开外链与系统分享会产生相应的外部通信。

本地删除会话不等于删除服务商已收到的请求或远端文件。服务端的数据处理规则由相应服务商决定。

## 两种接口模式

| | DeepSeek 专用模式 | OpenAI 兼容模式 |
| --- | --- | --- |
| 文本对话 | `/anthropic/v1/messages` | `/chat/completions` |
| 流式回复 | 解析专用消息事件及内容块 | 解析 `choices[0].delta.content` |
| 思考、联网搜索、链接阅读 | 客户端可携带对应扩展并展示返回；服务端需要支持 | 未发送这些 DeepSeek 专用扩展，也未解析各家专有推理字段 |
| 附件 | 接入专用上传与处理接口 | 需要兼容端点实现 Files API 和文件引用。官方 DeepSeek Pro 的文件输入受限。 |
| 语音输入 | 接入专用 ASR，需要麦克风权限和服务端支持 | 当前语音输入按钮禁用 |
| 回复朗读 | 调用所选服务商的专用 TTS 接口 | 关闭朗读入口 |
| 自动标题与提醒 | 可使用服务端扩展 | 当前文本适配未传递这些扩展 |

保存配置时的 `GET /models` 检查不能代替聊天、附件或语音的实际验证。内置服务商预设仅帮助填写地址、协议和模型，不表示对应账户或全部功能已经测试通过。

部分服务商的原生协议与 OpenAI 协议不同。例如当前 Anthropic 预设并没有增加 Anthropic 官方 Messages 适配；这类服务需要另行提供兼容端点。请按服务商公开文档核实，避免直接把预设视为兼容保证。

## 聊天导入与导出

客户端使用 `export_format_version: 3` 的历史格式，并通过可选 `deepchat_context` 扩展保存上下文选择与摘要来源。导入兼容 ZIP 时先确认、校验和暂存；校验完成后成功创建本机恢复点，才在事务中替换全部会话与附件。**导入不是合并。**

导出保留消息树、当前分支、上下文排除轮次、摘要检查点及本地存在的图片原件。单条删除后保留的回答带有原始问题归属，避免导入后错误配对。非图片附件仅保存元数据，不包含文件原件；API Key、应用偏好和未发送草稿不属于聊天导出，因此不能把 ZIP 当作完整应用快照。

自动备份默认每 10 个新完成用户轮次生成一次本机 ZIP，同一轮重新生成或续写不重复计数。生成、交付下载 / 分享、用户确认保存是三种独立状态；只有用户确认后才显示已保存。创建恢复点时另行保存全部本地附件原件和草稿，导入、清空、恢复前写入失败均中止替换。历史与草稿位于不同数据库，恢复草稿失败会明确报错且保留恢复前快照。清除应用数据或卸载会同时清除本机备份。

归档支持单卷 ZIP32 的 STORE / DEFLATE，不支持 ZIP64、加密 ZIP 或多卷归档。Android 下载历史链接使用原生文件下载；Web 使用 `fetch`，受链接有效期和跨域响应影响。格式细节见 [历史文件格式](../chat-demo/src/services/chat/history/README.md)。

## 上下文估算与压缩

上下文圆环是本地估算，依据所配置的窗口显示占用比例；不代表余额、精确 token 计费或模型实际拥有的上下文长度。DeepSeek 模式默认窗口为 1,000,000，OpenAI 模式为 128,000，可按实际模型修改。

可以逐轮包含或排除历史，也可快速选择最近 5 / 10 轮。实际请求和用量估算采用相同的当前分支、轮次选择与摘要来源校验。切换分支、排除摘要涵盖的轮次或删除摘要来源时，不会继续发送失效摘要。

达到 80% 后，用户可以确认手动摘要；默认关闭的自动摘要可在上下文面板启用，发送前预算达到阈值时调用当前模型。旧轮次超过单次摘要预算时按完整内容分批处理，不通过裁掉开头来凑窗口。近期保留预算目标约为窗口的 16%，并非固定保留 16% 的消息数。当前问题与续写前缀始终保留；取消、断流、空结果、拒绝、截断、配置变化或摘要未缩短时保留原文和旧摘要。

原始消息仍保存在本机。摘要可以查看与编辑，也可以恢复完整上下文。摘要可能遗漏细节或产生误记；长历史可能产生多次模型请求。重要记录应先导出备份。

## 删除范围

消息菜单支持仅删除当前消息或删除当前消息及全部后代，后者包含隐藏分支。三次确认依次核对范围、消息与最终删除；任何一步取消都不改变数据。最终执行时再次验证消息 ID 集合，范围已变或正在生成时拒绝删除。

单条删除会重接后续分支并保留所有其他消息。回答通过 `contextUserId` 记录原问题归属，孤立回答只展示，不参与请求轮次，也不能重新生成或继续。共享附件仍被其他消息引用时保留原件；摘要涵盖被删消息时清除摘要，防止继续发送已删除内容。
